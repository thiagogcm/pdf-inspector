# C API

A stable C ABI over the crate's public API, for consumers that cannot link Rust directly — C, C++, and the FFI layers of Go, C#, Swift, and similar. The header `pdf_inspector.h` is generated by [cbindgen](https://github.com/mozilla/cbindgen) and checked in; CI regenerates it and fails on drift.

## Building

The C symbols are behind the `c-api` cargo feature — without it the library builds normally but exports nothing.

```bash
cargo build --release --lib --features c-api
```

This produces `target/release/libpdf_inspector.a` and `libpdf_inspector.so` (`.dylib` on macOS). The shared library carries a SONAME (`libpdf_inspector.so.<major>` on Linux, `@rpath/libpdf_inspector.<major>.dylib` on macOS, tracking `PDF_INSPECTOR_ABI_VERSION`) so distro packaging and side-by-side installs of different major ABI versions resolve correctly; it is a no-op on Windows.

Static linking needs nothing extra:

```bash
cc -std=c11 -I. my_app.c target/release/libpdf_inspector.a -ldl -lpthread -lm -o my_app
```

Dynamic linking (`-lpdf_inspector`) does: `cargo build` produces only the unversioned `libpdf_inspector.so`, but the library's own SONAME — what a dynamically-linked consumer's `DT_NEEDED` entry actually records, and what the runtime linker looks for — is the _versioned_ name above. Without a same-named file or symlink next to `libpdf_inspector.so`, a consumer linked this way builds fine and then fails at load time with "cannot open shared object file". Real distro packaging supplies that file; building straight from this repo, create the symlink yourself first:

```bash
ln -sf libpdf_inspector.so target/release/libpdf_inspector.so.$(readelf -d target/release/libpdf_inspector.so | sed -n 's/.*(SONAME)[^[]*\[\(.*\)\]/\1/p' | sed 's/^libpdf_inspector\.so\.//')
cc -std=c11 -I. my_app.c -Ltarget/release -lpdf_inspector -ldl -lpthread -lm -o my_app
LD_LIBRARY_PATH=target/release ./my_app
```

`./scripts/test-c-consumer.sh` does exactly this (see its "dynamic-link smoke test" step) so this cannot silently regress.

The header is C11 and also compiles as C++. After changing `src/c_api.rs`, run `./scripts/generate-c-header.sh` (requires cbindgen 0.29.4) and `./scripts/test-c-consumer.sh`.

## Ownership and safety

- **Handles are caller-owned.** Release each one exactly once, with its documented `*_free` — passing a handle to a different `*_free` is undefined behaviour.
- **Returned pointers are borrowed.** Never free them; they stay valid until the owning handle is freed.
- **Strings use `CByteView`; page arrays use `CU32View`.** Each contains a borrowed `ptr` and `len`. String bytes are UTF-8, not NUL-terminated, and may contain NUL bytes, so never use `strlen`. View getters return `true` when the requested value is present, including a present-but-empty value with a non-NULL pointer and zero length. They return `false` for an absent value, invalid handle/index, or NULL output and zero the output view whenever one was supplied.
- **Getters are total.** A NULL handle or out-of-range index returns the type's zero value (`0`, `0.0`, `false`, NULL, or an `Unknown` enum variant), never a panic — they are written to always have a defined value, and carry no panic guard of their own (see below). Functions that allocate report failure through `PdfInspectorError` and leave their out-parameter NULL, unconditionally and before any other validation can fail.

Panics are caught **only at entry points that return `PdfInspectorError`**, collapsing into `PdfInspectorError_Panic` so unwinding never crosses the FFI boundary there. This depends on the crate being built with the default `panic = "unwind"` runtime: under `-C panic=abort` (or a workspace profile that sets it) every `catch_unwind` here becomes an abort, and this guarantee is void with no build-time signal. Getters return no error code, so they cannot report a panic that way; they are written to be total by construction instead (see above) and do not carry a panic guard, which would only cost every call performance for a failure mode they structurally cannot report. Handles are not synchronised: concurrent reads of one handle are fine, but any call that mutates or frees a handle must not race with another use of it.

## Error diagnostics

`map_error` (the internal `PdfError` → `PdfInspectorError` mapping) discards everything but the error code by default. `PdfInspectorError_ParseError` and `PdfInspectorError_NotAPdf` can carry more: the underlying `PdfError::Parse`/`PdfError::NotAPdf` variants wrap a diagnostic string (a lopdf parse failure, or a "file appears to be X" hint). Read it with `pdf_inspector_last_error_message(&view)`, which returns `true` when a diagnostic is present.

The diagnostic is scoped to **the calling thread's most recent `PdfInspectorError`-returning call** — not "the most recent call" in general. Getters and `*_free` return no `PdfInspectorError`, so they never touch this slot: reading it after one of those still reflects whatever the last fallible call left behind. Only a call that itself returns `PdfInspectorError` clears the slot at the start of the call (via the same internal panic-guard path every such function funnels through) and repopulates it if that call fails with a message. The borrowed view stays valid until the next such call on the same thread. Read it immediately after the failing call, on that same thread.

## Page numbers

Page numbers crossing this ABI are 1-indexed everywhere, with no exceptions: every page-list parameter (`extract_text_with_positions`, `extract_structure_elements`, `extract_pages_markdown`, `extract_text_in_regions`, `extract_tables_in_regions`, `detect_vector_grid_in_region`, `extract_tables_with_structure_auto`, `extract_tables_with_structure_cells`, `pdf_inspector_options_add_page`, and `pdf_inspector_options_set_scan_strategy` with `CScanStrategy_Pages`), every per-item page field (`CTextItemDescriptor.page`, `CPdfRect.page`), and every page number a getter returns (including full-detector OCR pages and `pdf_inspector_classification_get_pages_needing_ocr`, even though the underlying Rust `PdfClassification::pages_needing_ocr` it wraps is documented as 0-indexed) is 1-indexed. Passing 0 anywhere a page number is accepted returns `PdfInspectorError_InvalidArgument`. The corresponding Rust region, vector-grid, and TSR APIs take 0-indexed pages; the C shim converts their input so C callers use 1-indexed pages there like everywhere else.

This ABI does **not** reject a page number greater than the document's page count — that behaviour originates in the Rust layer (`extract_pages_markdown` and region extraction return phantom entries that need OCR rather than an error) and is out of scope for the C shim to change. Do not rely on an out-of-range page number failing; obtain the document's page count first if you need to validate a caller-supplied page number.

## Passwords

Every extraction and classification entry point that reads a PDF accepts a password: `pdf_inspector_process_pdf`/`_mem` and `pdf_inspector_detect_pdf_type`/`_mem` take it through `PdfOptions` (`pdf_inspector_options_set_password`), and `pdf_inspector_extract_text`, `_extract_text_mem`, `_extract_text_with_positions`, `_mem`, `_extract_structure_elements`, `_mem`, `_extract_pages_markdown`, `_mem`, `_extract_text_in_regions`, `_mem`, `_extract_tables_in_regions`, `_mem`, `pdf_inspector_detect_vector_grid_in_region`, `_mem`, `pdf_inspector_extract_tables_with_structure_auto`, `_mem`, `pdf_inspector_extract_tables_with_structure_cells`, `_mem`, and `pdf_inspector_classify_pdf_mem` each take a `password` parameter directly. In every case, NULL means "no password" (falling back to the empty password, i.e. owner-only encryption) — the same convention `pdf_inspector_options_set_password` uses to clear one. A wrong password falls back to retrying with the empty one, so on an owner-only-encrypted PDF a wrong password **succeeds** exactly as no password would; it returns `PdfInspectorError_Encrypted` only when the empty password also fails.

## Example

```c
#include "pdf_inspector.h"
#include <stdio.h>

int main(void) {
    CPdfOptions *options = NULL;
    if (pdf_inspector_options_new(&options) != PdfInspectorError_Success) {
        return 1;
    }
    pdf_inspector_options_set_mode(options, CProcessMode_Full);

    CPdfProcessResult *result = NULL;
    if (pdf_inspector_process_pdf("input.pdf", options, &result) != PdfInspectorError_Success) {
        pdf_inspector_options_free(options);
        return 1;
    }

    CByteView markdown = {0};
    if (pdf_inspector_result_get_markdown(result, &markdown)) {
        fwrite(markdown.ptr, 1, markdown.len, stdout); // borrowed; do not free
    }

    pdf_inspector_result_free(result);
    pdf_inspector_options_free(options);
    return 0;
}
```

`tests/c_consumer.c` is a fuller example, compiled under `-Wall -Wextra -Werror` in CI (twice: once with the default enum ABI, once with `-fshort-enums`; see [Enum width](#enum-width) below), and also compiled and run under AddressSanitizer + UndefinedBehaviorSanitizer.

## Surface

| Area | Functions |
| --- | --- |
| Version / diagnostics | `pdf_inspector_abi_version`, `_abi_minor`, `_last_error_message` |
| Triage | `pdf_inspector_estimate_page_count_from_bytes`, `pdf_inspector_ocr_reason_from_string` |
| Options | `pdf_inspector_options_new` / `_free` (→ `CPdfOptions`), `_set_mode`, `_set_password`, `_add_page`, `_clear_pages`, `_set_profile`, `_set_base_font_size`, `_set_scan_strategy`, and per-flag markdown/detection setters |
| Processing | `pdf_inspector_process_pdf`, `_process_pdf_mem` → `CPdfProcessResult` |
| Full type detection | `pdf_inspector_detect_pdf_type`, `_detect_pdf_type_mem` → `CPdfTypeResult` |
| Classification | `pdf_inspector_classify_pdf`, `_classify_pdf_mem` → `CPdfClassification` |
| Plain text | `pdf_inspector_extract_text`, `_extract_text_mem` → `CTextResult` |
| Plain-text Markdown | `pdf_inspector_to_markdown` → `CTextResult` |
| Positioned text | `pdf_inspector_extract_text_with_positions`, `_mem` and `pdf_inspector_text_items_result_new`, `_add` → `CTextItemsResult`; `pdf_inspector_to_markdown_from_items` → `CTextResult` |
| Tagged structure | `pdf_inspector_extract_structure_elements`, `_mem` → `CStructureElementsResult` |
| Per-page markdown | `pdf_inspector_extract_pages_markdown`, `_mem` → `CPagesExtractionResult` |
| Region text | `pdf_inspector_extract_text_in_regions`, `_mem` → `CRegionTextResult` |
| Region tables | `pdf_inspector_extract_tables_in_regions`, `_mem` → `CRegionTextResult` |
| Vector-grid detection | `pdf_inspector_detect_vector_grid_in_region`, `_mem` → `CVectorGridResult` |
| TSR table extraction | `pdf_inspector_extract_tables_with_structure_auto`, `_mem` (repaired) and `pdf_inspector_extract_tables_with_structure`, `_mem` (raw) → `CTsrTableExtractionResult` |
| TSR structured cells | `pdf_inspector_extract_tables_with_structure_cells`, `_mem` → `CTsrStructuredCellsResult` |

A positioned item is read in two parts. `pdf_inspector_text_items_result_get_metrics` copies every numeric and flag field at once into a `CTextItemMetrics` — page, coordinates, font size, item type, the `PDF_INSPECTOR_TEXT_ITEM_FLAG_*` bits, and the MCID. Its four string fields stay on their own borrowed-view getters, because a borrowed pointer inside a copied struct would not share the struct's lifetime rules; `CTsrStructuredCell` splits the same way. `CTextItemMetrics` is field-for-field the non-string half of `CTextItemDescriptor`, so an item written through the descriptor reads back unchanged.

MCID absence is carried by `PDF_INSPECTOR_TEXT_ITEM_FLAG_HAS_MCID`, not by a zero: MCID 0 is the first marked-content ID on every page. `pdf_inspector_structure_elements_result_get_mcid` reports absence through its `bool` return for the same reason.

Two font getters, two different names. `pdf_inspector_text_items_result_get_font` returns the PDF font family (`/BaseFont`), such as `ABCDEF+CMMI10`. `pdf_inspector_text_items_result_get_font_tag` returns the page-local resource tag the content stream selected the font by, such as `F2` — present but empty for items with no originating PDF font resource, which is every caller-built item that does not supply one. For a small set of Distiller CID resource names, the resource name (for example, `C2_0`) is also retained in the family because it carries encoding information needed by extraction.

Full type detection exposes every field from Rust's `PdfTypeResult`: PDF type, total pages, sampled pages, sampled pages with text, confidence, optional title, OCR recommendation, 1-indexed OCR pages, and ordered per-page OCR reason strings. It accepts `PdfOptions` for consistency with processing, but observes only `detection` and `password`; processing mode, Markdown settings, and page filters are ignored. A NULL options pointer uses defaults.

Plain-text Markdown conversion accepts length-delimited UTF-8, including embedded NUL bytes; invalid UTF-8 returns `PdfInspectorError_InvalidUtf8`. It runs Rust's basic `to_markdown` conversion, which currently recognizes lists and code-like lines. It does not have font, geometry, link, image, page, or structure-tree information, so the richer formatting options that require positioned PDF items have no effect. Only `PdfOptions.markdown` is passed to the converter; processing mode, detection settings, password, and page filters are ignored. A NULL options pointer uses defaults.

Positioned-item Markdown conversion borrows an existing `CTextItemsResult`, leaving it valid and reusable, and returns an independent `CTextResult`. It applies font, style, item-type, link, coordinate, and page information already present in the items. Two further inputs feed document-level decisions: an optional borrowed `CPdfRect` array (PDF `re`-operator rectangles, in the same bottom-left-origin PDF-point space as item coordinates) enables rectangle-based table detection, and `document_page_count` supplies the owning PDF's authoritative page count so trailing blank or unextracted pages contribute to document-wide header, footer, and folio coverage — pass 0 (it is a count, not a page number, so the page-zero rule does not apply) to fall back to the highest item page. No path-line geometry or structure-tree context is available on this path. The conversion clones the source items because the Rust converter consumes its input. Only `PdfOptions.markdown` is observed; a NULL options pointer uses defaults.

Caller-built positioned items close the OCR round trip: region extraction reports `needs_ocr` regions, the caller runs its own OCR, and `pdf_inspector_text_items_result_new` plus `pdf_inspector_text_items_result_add` turn that output into a `CTextItemsResult` accepted everywhere an extracted one is — the getters and `pdf_inspector_to_markdown_from_items` included — and freed the same way. `_add` takes a borrowed array of `CTextItemDescriptor` values and copies every string, so the input needs to remain valid only for the duration of the call; it is atomic for every `PdfInspectorError` it reports, appending nothing when any descriptor is rejected. `PdfInspectorError_Panic` is the one exception: an allocation failure while appending an already-validated batch can leave part of it in place. Descriptor coordinates use the same bottom-left-origin PDF-point space the positioned-item getters return (not region extraction's top-left origin). The per-field contract — item types, the `PDF_INSPECTOR_TEXT_ITEM_FLAG_*` bits, and what is rejected — is documented on `CTextItemDescriptor` in the header; descriptor pages follow the [page-number rule](#page-numbers) like everything else.

Join positioned text to semantic roles by matching `(page, mcid)` between `CTextItemsResult` and `CStructureElementsResult`, checking `pdf_inspector_text_items_result_has_mcid` before reading an item's MCID.

Region extraction takes an array of `CPageRegions` descriptors. Each descriptor has a 1-indexed page number and a borrowed array of `CRegion` rectangles in PDF points with a top-left origin. The output preserves both array dimensions and input order. Input arrays need to remain valid only for the duration of the call; the result handle owns its output.

Region-table extraction uses the same descriptors and result handle. When a table is detected, the region text contains a Markdown pipe table and `needs_ocr` is false. When no reliable table is found, the text is empty and `needs_ocr` is true so callers can fall back to OCR.

Vector-grid detection inspects one region for ruled-line or rectangle table geometry. A successful call always returns a `CVectorGridResult`, including when no grid is found; check `pdf_inspector_vector_grid_result_is_detected` before reading its HTML-like structure tokens and crop-image-pixel cell boxes. The cell coordinates use a top-left origin at the supplied region's top-left corner and are scaled to `render_dpi`. The DPI must be finite and positive, and its scaled crop dimensions must remain finite.

TSR table extraction accepts a batch of `CTsrTableInput` descriptors and returns one result per input in the same order. Each input contains a 1-indexed page, an ordered positive-area crop in top-left-origin PDF points, a finite positive render DPI, borrowed UTF-8 structure-token views, and borrowed cell boxes in crop-image pixels. Each `CTsrCellBBox` must contain exactly four rectangle coordinates or eight polygon coordinates; the number of boxes must equal the number of cells parsed from the token stream. Row spans must fit the declared rows and column spans are limited to 25. Nested arrays remain the caller's property and need to remain valid only for the duration of the call. Result Markdown and optional stable fallback-reason labels are borrowed from `CTsrTableExtractionResult` and remain valid until it is freed. The auto path repairs known TSR pathologies or falls back to heuristic extraction where appropriate.

`pdf_inspector_extract_tables_with_structure`/`_mem` render the same descriptors with no quality repair and no heuristic fallback, so a pathological token stream produces a pathological table; their fallback reason is always absent. Use them to compare the two paths (eval harnesses) and the auto path in production.

The raw structured-cell path accepts the same descriptors but returns each resolved cell's row, column, spans, header status, native PDF text, and normalized page-point bounding box. It does not run the auto path's quality repair or heuristic fallback, whose output cannot always be represented as TSR cells. Fixed metadata is copied into `CTsrStructuredCell`; text is a borrowed `CByteView` valid until `CTsrStructuredCellsResult` is freed.

**Explicitly out of scope** (not part of this ABI): the path-line-aware positioned-item Markdown variant (crate-private on the Rust side), `collect_text_in_region` (it operates on a caller-held item slice the ABI has no representation for), the `re`-rectangle-returning extraction variants (crate-private, so rectangles can be supplied to `pdf_inspector_to_markdown_from_items` but not obtained from a PDF through this ABI), and any vision/OCR surface.

## OCR reasons

The reason strings the OCR-reason getters return are stable identifiers, not display text. `pdf_inspector_ocr_reason_from_string` maps one onto a `COcrReason` discriminant so a consumer can `switch` on it instead of keeping its own table of string literals. A reason this library does not define — including one added by a newer runtime than the header was generated from — maps to `COcrReason_Unknown`, leaving the raw bytes available to handle directly.

## Enum width

Every `enum` this header declares (`PdfInspectorError`, `CPdfType`, `CTextItemType`, `CProcessMode`, `CMarkdownProfile`, `CScanStrategy`, `COcrReason`) carries a trailing `_ReservedMax = 2147483647` enumerator. It is not a real value — no C caller should pass or match it — and exists only so its discriminant cannot fit in anything smaller than `int`, forcing the C compiler to use a 4-byte representation. Without it, a consumer compiled with `-fshort-enums` (the default ABI on bare-metal ARM AAPCS and some Android NDK configs) would size these enums at 1 byte, silently mismatching Rust's `#[repr(C)]` enums, which are always 4 bytes. `tests/c_consumer.c` asserts `sizeof(...)  == 4` for all seven under both the default and `-fshort-enums` compiles (see `scripts/test-c-consumer.sh`).

## Versioning

Two independent values, both readable at runtime so a consumer that loads the shared library dynamically can confirm compatibility with the header it compiled against:

- `PDF_INSPECTOR_ABI_VERSION` / `pdf_inspector_abi_version()` — the **major** version. Bumped only for incompatible changes: removing or renaming a function, changing a signature, or changing the meaning of an existing value.
- `PDF_INSPECTOR_ABI_MINOR` / `pdf_inspector_abi_minor()` — the **minor** version. Bumped for additive, backward-compatible changes (a new function, a new enum variant appended at the end); reset to 0 on every major bump.

A conforming consumer must check **both**:

```c
if (pdf_inspector_abi_version() != PDF_INSPECTOR_ABI_VERSION ||
    pdf_inspector_abi_minor() < PDF_INSPECTOR_ABI_MINOR) {
    // Incompatible: either a different major version, or a runtime library
    // built before a minor version this consumer's header already relies on
    // (e.g. a function that exists in the header but not yet in the .so).
}
```

Checking only the major version is not enough: a consumer built against a _newer_ header than the `.so` it loads at runtime would see a matching major version, pass that check, and then fail at dynamic symbol resolution instead, looking up a function the older library does not export.

The current ABI version is 1.0. No consumer has shipped against it yet, so the surface may still change without a version bump. The bump discipline above takes effect once version 1 actually ships.

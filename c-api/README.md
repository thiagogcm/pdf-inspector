# C API observations

The exported records in `pdf_inspector.h` are owned by the document or execution result. Copy observations before freeing their owner. The header and handwritten consumers evolve together.

`PdfPageInfo.user_unit` is the page-local `/UserUnit`, defaulting to 1. Opening refuses nonnumeric values and values outside `(0, 75000]`. Page sizes, positioned geometry and OCR polygons remain in native user-space units. Convert from sheet to display space first, then multiply by this value for physical points. The pinned PDFium reports native units for both page dimensions and pixel-to-page transforms.

`PDF_OUT_OCR_SPANS` runs the core's public renderer/OCR orchestration and returns raw recognition independently from Markdown fusion. It cannot be combined with `PDF_OUT_MARKDOWN`; `PDF_OUT_TEXT` still requests native text. OCR routing and minimum confidence come from the request. Spans keep exact text, polygons and individual confidence in the request frame. Page provenance records model identity and timing. The C API retains observations while releasing each page's bitmap before recognizing the next page.

A `RASTER` or `ANALYSIS` request returns `PdfPage.image_coverage` when `PDF_PAGE_IMAGE_COVERAGE` is set. This is the detector's existing 64-by-64 grid estimate of executed image coverage, bounded by the sum of painted image areas. It follows its clipping, form and pattern rules; resource inventory alone is not coverage. An incomplete walk, failed page-stream decoding, or a filtered page stream exceeding a default 32 MiB decoded validation budget leaves coverage absent. Image DPI remains unavailable.

The `PDF_OUT_RASTER` projection reads selected pages from the open document. The usual document classification still accompanies the result and is cached once for default detection options. Its `ocr_reasons` contains positive `invisible_text_layer` and `scanned` signals, in that order, independently of document sampling. These reuse the core detector's default per-page gates and reason labels, including low-resolution image-backed pages below the bare text-operator floor. Positive reasons require completed, nonzero executed-image coverage; an unused image resource or failed walk cannot establish a scan. An empty list leaves scan status unassessed. It does not assess text quality, layout, tables or columns, skip invisible text, produce Markdown, or change native OCR routing. `PDF_OUT_ANALYSIS` retains the richer Markdown-based analysis with document-wide font and layout context. Combining projections retains their usual analysis; enabled OCR can also supply its routing reasons and analysis flags. Use OCR off for raster-only observations.

`PDF_OUT_STRUCTURE_ROLES` returns each selected page's MCID roles in `PdfPage.structure`, without `PdfResult.structure_nodes`. The role lookup is cached once per document; requests do not traverse the document tree again. `PDF_OUT_STRUCTURE` continues to return both the page roles and the selected semantic tree. These projections share the existing records and ownership rules.

Run `cargo test --manifest-path c-api/Cargo.toml`, `cargo clippy --manifest-path c-api/Cargo.toml --all-targets --features render-pdfium,ocr -- -D warnings` and `c-api/scripts/test-c-consumer.sh` for the C API checks. Rendering and recognition require explicitly configured PDFium, ONNX Runtime and models.

For the runtime smoke tests, set `PDFIUM_LIB_PATH` and `ORT_DYLIB_PATH` to absolute library files and `PDF_INSPECTOR_OCR_TEST_MODELS` to the provisioned model directory. When models are supplied, both library paths are required. The test loads the libraries through the C API before preparing OCR sessions, matching a host's initialization order. Run the render/OCR feature suite with these values to exercise actual recognition and both fused Markdown and raw-span provenance.
